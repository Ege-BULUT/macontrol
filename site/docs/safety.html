Safety model

macontrol is built to be careful with your files. Unless you turn on hardcore mode, nothing is deleted permanently, and every item passes the same checks before it moves or is deleted.

What happens to one item

  1. You choose it. In Clean only Safe items start selected, and in Debloat no app does. Every removal ends in a confirmation that lists exactly what will move.
  2. It is checked again. Right before the move, the item is compared with what the scan saw. A file that was replaced, or swapped for a link, since the scan stays where it is.
  3. Protected places are refused. The path is resolved first, so a different route to the same folder does not slip past.
  4. It goes to the Trash through macOS's own Move to Trash, which also records Finder's Put Back. macontrol never empties the Trash: the space comes back when you do.
  5. It is written to the journal, so History can put it back.

If a check fails, that item stays where it is and the result says why.

In hardcore mode, step 4 changes: a file is deleted where it is, and a folder goes to the Trash first and is then erased there, through open folder handles, so a folder swapped for a link halfway through is never followed. The journal records the deletion, with no Undo. Items in iCloud Drive or another cloud folder, and your notes, contacts, calendars, Safari data and iPhone backups, still go to the Trash.

Protected places

These are never moved to the Trash, and neither is any folder that contains them: your home folder, Desktop, Documents, Downloads, Pictures, Movies and Music, your Library and its standard folders, /Applications, /Library and system folders. What is inside them can be removed, one item at a time, when you choose it.

These are off limits entirely, contents included: Keychains, ~/.ssh, ~/.gnupg, Mail, Messages, photo libraries, privacy (TCC) data, cloud sync state and /System.

A file you locked in Finder is refused, and so is a folder that holds one, because moving the folder would carry the locked file into the Trash. Anything macOS marks as restricted is refused too. macontrol never changes flags or ownership to force a removal.

Cloud folders need consent

Items in iCloud Drive or another cloud storage folder need an extra confirmation, because removing them removes them on every device.

The undo journal

Every removed item gets a line in ~/Library/Application Support/Macontrol/trash-journal.jsonl, readable only by you: its batch, original path, place in the Trash, identity and size. History uses it to put a batch back, as long as the items are still in the Trash and their original place is free. Items keep their names in the Trash, so a crash in the middle of a batch leaves nothing hidden.

Clean and Uninstall are cautious

  • Every catalog rule is checked when the catalog loads. A pattern that reaches outside the folders it is meant for drops the whole rule.
  • Clean skips anything changed in the last 10 minutes and anything that belongs to a running app.
  • Uninstall only preselects leftovers that carry the app's bundle identifier. Name-only matches and data shared with another app wait for you.
  • Uninstall asks the app to quit and never forces it.

Admin powers, fenced in

Root-owned items are removed only in Clean, Uninstall and Debloat, only after macOS's administrator dialog, and only by the helper inside the app. The helper acts only on app bundles in /Applications, items inside a few /Library folders, package receipts and root-owned items in your own Library, and it runs every check on this page again as root before it acts. The list it works from is bound to the dialog by its SHA-256, so a list changed afterwards is refused. Admin removals has the details. The Disk Map never uses it.

No network

macontrol has no networking code: it does not phone home, check for updates or send what it scans anywhere.

How this is tested

  • One door. Only the Safety module can move or delete files. A test fails if any other source file deletes, moves or renames files, runs a script or launches a process. The exceptions are named in the test: launchctl, which stops an app's own background jobs, Xcode's own simctl for simulator runtimes, tmutil for restore points, and the one call that starts the administrator helper.
  • Attack suite. Tests swap folders for links in the middle of a batch and of a permanent erase, use hostile file names, locked files and paths deeper than PATH_MAX, rewrite the helper's list after the password, replay old helper results, and compare whole folder trees before, after and after Undo.
  • Only in temporary folders. Tests build their files in temporary folders and never touch real data or the real Trash.

What is not verified yet

The administrator helper has run only as a normal user, in tests. Its first real run as root, with an administrator password on a real Mac, is still to come (T-0078 on the project board).
