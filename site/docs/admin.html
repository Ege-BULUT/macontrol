Admin removals

Some apps and leftovers belong to the system, so only an administrator can remove them. macontrol does that through a small helper that macOS starts after you enter your password.

Preview. The helper's checks and both removal modes are tested as a normal user, on temporary folders. Its first real run as root, with an administrator password on a real Mac, is still to come (T-0078 on the project board).

Which items need it

Items owned by root, such as:

  • Apple's App Store apps in /Applications: GarageBand, iMovie, Pages, Numbers, Keynote and the like.
  • Leftovers in /Library: Application Support, Caches, Logs, Preferences, LaunchDaemons and LaunchAgents, privileged helper tools.
  • Package receipts in /private/var/db/receipts, and content that Apple's apps install, such as sound libraries and simulator caches.
  • Anything a root process left in your own Library.

In Clean, Uninstall and Debloat they carry an Admin badge and can be ticked like any other item. The Disk Map does not use the helper: root-owned items there stay marked Needs admin, with Reveal in Finder.

The password prompt

The confirmation says it under “Also happens”: “macOS asks for your administrator password for 3 items owned by the system.” When you confirm, macOS shows its own administrator dialog, with macontrol's message in it:

  • “macontrol needs your administrator password to move 3 items owned by the system to the Trash.”
  • “macontrol needs your administrator password to delete 3 items owned by the system permanently.”, in hardcore mode.

Everything that needs root in one removal goes in one request, so one Debloat run of several apps shows one dialog. macOS may ask again for the next removal, even a few minutes later. If you cancel the dialog, none of those items is touched, and the result says so. macontrol never sees or stores your password: the dialog belongs to macOS.

What the helper does

The helper, Contents/Helpers/macontrol-priv, lives inside the signed app. It is not installed anywhere, and it exits when the removal is done.

  1. macontrol writes the list you confirmed into a request file that only you can read, and hands the helper the file's SHA-256 through the dialog. If the file changes after that, the helper refuses it.
  2. As root, the helper checks each item again: that it lies in a place root may act, that it is not protected, that it is still the item the scan saw, and that it is not locked.
  3. It moves each item to your Trash, or deletes it in hardcore mode, and writes each result to a file only root can write. macontrol shows the results as they come in.

What it can and can't touch

The helper may act only on:

  • App bundles in /Applications, or one folder down, never /Applications itself or a folder in it.
  • Items inside /Library's Application Support, Audio, Caches, Developer, LaunchAgents, LaunchDaemons, Logs, Preferences and PrivilegedHelperTools folders, never those folders themselves.
  • Package receipts in /private/var/db/receipts.
  • Root-owned items in your own Library.

Everything else is refused, including /System, /private/etc, keychains, extensions, macOS's own settings inside the folders above, other users' folders, locked files, and anything that changed since the scan.

The helper never changes permissions, ownership or flags to force a removal. A background job in /Library/LaunchDaemons is stopped first only when macOS confirms it was started from that exact file; otherwise its file is still removed, and the result says its background service may keep running until the next restart.

Putting items back

Items the helper moved are in your Trash, still owned by the system. History can't put them back itself: drag them back in Finder, which may ask for your password. Finder may also ask for it when you empty the Trash.
