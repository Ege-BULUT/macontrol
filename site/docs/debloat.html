Debloat

Debloat removes Apple's optional apps and what they install outside their bundle, from one checklist. It is the fifth section in the sidebar, ⌘5.

What it lists

  • Apple apps you can remove: Xcode, GarageBand, Logic Pro, MainStage, iMovie, Pages, Numbers, Keynote, Final Cut Pro, Motion and Compressor, when they are installed. Each row expands to the content the app installs, with its size.
  • Installers: Apple's “Install macOS” apps.
  • Part of macOS (locked): apps on the sealed system volume. Selecting one explains why macOS keeps it. See macOS's own apps.

What starts ticked

No app starts ticked. When you tick one, its bundle and the content macontrol has checked for it are ticked with it. These stay unticked, with a note that says why:

  • Content another app also uses: “Also used by Logic Pro, which is installed.”
  • Content of an app whose install macontrol hasn't checked yet: “macontrol hasn't checked this location on a real install yet.”
  • Content that holds your own work, such as the apps and data inside Xcode's simulators, and, in hardcore mode, an app's containers: “May hold documents you made in Pages.”

Items that macOS itself restricts are listed as “Kept by macOS”, without a checkbox. Your own files, such as ~/Music/GarageBand and Xcode archives, and the Command Line Tools that git and clang use, are never listed.

Which apps are checked

The content each app installs comes from a list built into the signed app. Only Xcode's has been checked against a real install (Xcode 26.6 on macOS 26.6). The others come from Apple's install layout; until each one is checked on a Mac that has it, none of its content starts ticked.

Xcode

Xcode's simulator runtimes are deleted first, with CoreSimulator's own tool, while Xcode is still there to do it: the tool lives in a folder the Xcode removal takes away. Runtimes can't go to the Trash, so in Trash mode their row starts unticked, under “Deleted by Xcode's tool, not moved to the Trash”, with the note “Download them again in Xcode › Settings › Components.” If a runtime can't be deleted, Xcode is kept, because without it nothing could delete them later.

If git and clang point into the Xcode you remove, the confirmation says: “git, clang and other developer tools stop working until you run sudo xcode-select --reset in Terminal.”, with a Copy button.

Removing

Remove… opens a confirmation that lists every item and, under “Also happens”, what else will happen: apps asked to quit, background jobs stopped, runtimes deleted first, the administrator password. Everything owned by the system goes to the administrator helper in one request, so the whole run shows one password dialog. If one app can't be removed, for example because it won't quit, the others still go, and the result says which one stayed.

In this preview Debloat's hardcore confirmation has no restore point box, and its “Frees up to” includes simulator runtimes that are named only in its notes (T-0086).
